# `math` conformance vectors

Bit-exact test vectors for the deterministic math shared by all implementations
(`det_math` in Rust: `rust/crates/la-expr/src/det_math/`; TypeScript:
`ts/packages/core/src/detmath.ts` and `pcg.ts`). Spec: `spec/spec.md` §10.4.

Every implementation MUST reproduce every output **bit for bit**. The vectors are
generated by the Rust implementation:

```sh
cd rust && cargo run -p label-anything-expr --example gen_math_vectors   # rewrites this directory
```

The generator is deterministic (inputs come from PCG32 and exact bit manipulation), so
re-running it reproduces the files byte for byte unless the implementation changed.

Runners: Rust `cargo test -p label-anything-expr --test conformance_math`; TypeScript
`npx vitest run packages/core/test/detmath packages/core/test/pcg` (from `ts/`).

## Function files (`<function>.json`)

```jsonc
{
  "kind": "math",
  "function": "pow",          // det_math function (Rust name)
  "inputs": 2,                // number of f64 arguments
  "outputs": 1,               // number of f64 results
  "description": "pow(x, y): [x, y, result]",
  "generated_by": "rust/crates/la-expr/examples/gen_math_vectors.rs",
  "vectors": [
    ["0x4000000000000000", "0x3fe0000000000000", "0x3ff6a09e667f3bcd"],
    …
  ]
}
```

* Each vector lists the inputs, then the outputs (`sin_cos_deg`: `[deg, sin, cos]`).
* Every number is the IEEE-754 binary64 bit pattern of the value as `"0x"` followed by
  exactly 16 lower-case hex digits (the `u64` from `f64::to_bits`, most significant digit
  first; independent of the platform's byte order).
* NaN: an expected `"0x7ff8000000000000"` matches **any** NaN result (platforms may
  canonicalize NaN payloads, e.g. when a JS engine stores NaN in a typed array).
  Implementations return the canonical quiet NaN. NaN inputs are only the canonical NaN.
* Signed zeros are significant: `0x0000000000000000` ≠ `0x8000000000000000`.

| file | function | vectors | inputs covered |
|---|---|---|---|
| `ln.json` | `ln(x)` | 1055 | specials (±0, <0, subnormals, ±inf, NaN, around √2 and 1), all 47 reduction buckets j/64 at three scales, random bit patterns, [0.5, 2], 1 ± 2^-60…2^-2 |
| `ln_1p.json` | `ln_1p(x)` | 986 | −1 and its neighbours, the 2^-54 and 2^-20 thresholds, √½−1, √2−1, huge values, log-uniform both signs |
| `exp.json` | `exp(x)` | 991 | overflow/underflow thresholds, subnormal results, tiny arguments, near k·ln2/2 |
| `pow.json` | `pow(x, y)` | 1113 | the full C99 special-case grid (±0, ±1, ±2, ±0.5, ±3, ±inf, NaN × 18 exponents), overflow/underflow edges, integer exponents (repeated squaring) incl. beyond 2^30, real exponents, x near 1 with huge y |
| `sin_cos_deg.json` | `sin_cos_deg(deg)` | 872 | every multiple of 15° in [−720°, 720°], ±0, huge and tiny angles, neighbours of 45°/90°/135°/315°/360°, random |
| `atan2_deg.json` | `atan2_deg(y, x)` | 769 | the 11 × 11 grid of specials (±0, ±1, ±inf, NaN, ±5e-324, ±MAX), the 9 reduction buckets and their edges, equal magnitudes, extreme ratios |
| `cbrt.json` | `cbrt(x)` | 641 | specials, exact cubes, random bit patterns, [1, 8) |
| `floor.json`, `ceil.json`, `trunc.json`, `round_half_away.json` | rounding | 534 each | ±0, halves, 0.49999999999999994, 2^52 − 0.5, 2^52, 2^53, subnormals, ±inf, NaN, random |

## `pcg32.json`

```jsonc
{
  "kind": "math", "function": "pcg32",
  "streams":    [ { "seed": "0x000000000000002a", "next_u32": ["0x…", … 1000 values] } ],
  "next_below": [ { "seed": "0x…", "n": 10, "values": [3, 7, …] } ],
  "next_f64":   [ { "seed": "0x…", "values": ["0x3fe…", …] } ],
  "shuffle":    [ { "seed": "0x…", "len": 10, "result": [7, 2, …], "next_u32_after": "0x…" } ]
}
```

* `seed`: the `u64` seed as 16 hex digits; outputs of `next_u32` as 8 hex digits.
* `streams`: the first 1000 `next_u32()` outputs of `Pcg32::new(seed)` for the seeds 0, 1,
  42 and 2³²−1.
* `next_below`: 64 successive `next_below(n)` results of a fresh generator (including
  n = 0 → 0, n = 1, n = 2³¹+1 and n = 2³²−1).
* `next_f64`: 32 successive `next_f64()` results (f64 bit patterns), one seed above 2⁵³.
* `shuffle`: `shuffle([0, 1, …, len−1])` of a fresh generator and the next `next_u32()`
  afterwards (so the number of consumed outputs is checked too).

The algorithm (spec §10.4): PCG-XSH-RR 64/32, multiplier 6364136223846793005,
increment 1442695040888963407, seeding `state = 0; step(); state += seed; step()`.
The vectors were cross-checked against an independent Python implementation of the
reference `pcg32_random_r`.

## Accuracy

`det_math` is bit-identical across implementations by construction (only IEEE `+ − × ÷`,
`sqrt` and exact operations, identical operation order); in addition it is accurate.
`check_accuracy.py` measures the error against correctly rounded mpmath references:

```sh
pip install mpmath
python3 conformance/math/check_accuracy.py                 # the vectors in this directory
cd rust && cargo run --release -p label-anything-expr --example gen_math_vectors -- --dump /tmp/d 1000000
python3 conformance/math/check_accuracy.py --dump /tmp/d   # plus 10^6 random samples per function
```

Measured maximum error (ulps of the exact result, normal results; 10⁶ random samples
per function plus the vectors here):

| function | max error | method |
|---|---|---|
| `ln`, `ln_1p` | 0.5000 | 47-entry table of ln(j/64), atanh series, all in double-double |
| `exp` | 0.5232 | Cody–Waite reduction, 1 + hi + r²/2 exact, Taylor tail |
| `pow` | 0.5241 | double-double `ln`, exact product, `exp` with tail; integer y by double-double repeated squaring |
| `sin_cos_deg` | 0.5379 | exact reduction in degrees, double-double π/180, Taylor kernels |
| `atan2_deg` | 0.5022 | 9-point table of atan(j/8)°, Taylor series in double-double |
| `cbrt` | 0.5000 | cubic start, two Newton steps, exact-residual correction |
| `floor`, `ceil`, `trunc`, `round_half_away` | exact | |

Results in the subnormal range may additionally be off by one ulp (double rounding).
Against the platform functions (Rust `std`/glibc in `tests/det_math_accuracy.rs`, JS
`Math` in `ts/packages/core/test/detmath-accuracy.test.ts`) the difference is at most
1 ulp, except for `sin`/`cos`/`atan2` evaluated by the platform through a rounded radian
conversion (`Math.sin(d * Math.PI / 180)`, `Math.atan2(y, x) * 180 / Math.PI`), where it
is at most 2 ulp (the platform's conversion is the less accurate side).
